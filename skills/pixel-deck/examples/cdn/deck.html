Explainer · Web performance

How a CDN serves a request

A CDN keeps copies of your files on edge servers near users, so most requests never travel to the origin.

The cast

Step 1 · Routing

DNS sends each user to a nearby edge

The URL stays the same. DNS or anycast routing answers with the address of an edge server close to the user.

Lookup

Another user in another city gets a different edge for the same URL.

Readout

Same URL

The browser asks for cdn.example.com/logo.png as usual.

Nearest edge

DNS picks edge B because it is closest.

Why it matters

A short network path means a short round trip.

Step 2 · Cache hit

Hit: the edge already has a fresh copy

The edge looks the URL up in its cache, finds a copy younger than its max-age, and answers on its own.

At the edge

The Age header tells the browser how long the copy has sat in the cache.

Readout

Cache key

Usually the URL: host plus path.

Fresh

42 s is below max-age=300, so the copy is served as is.

Origin

Not contacted at all. This is the fast path.

Step 3 · Cache miss

Miss: one trip to the origin, then store it

No copy at the edge, so it fetches the file from the origin, keeps it for as long as Cache-Control allows, and answers.

At the edge

One miss warms the edge for every nearby user after it.

Readout

Miss

The first request here pays the long trip to the origin.

Store

Cache-Control: max-age=300 lets the edge keep the copy for 300 s.

Next user

A nearby user a moment later gets a hit.

Step 4 · Expiry

After max-age: revalidate, don't re-download

A stale copy is kept. The edge asks the origin if the file changed; 304 Not Modified means keep using it.

Revalidation

ETag "v7" is the version tag the origin sent with the file.

Readout

Stale

Past max-age, the copy must be checked before it is served.

Conditional GET

The edge sends the copy's ETag in If-None-Match.

304

Headers only, no body: far cheaper than the full file.

Takeaway

Most requests should end at the edge

Each kind of request costs a different trip. Cache-Control decides which one you get.

Remember

  1. A hit is served by the edge alone.
  2. A miss pays one origin trip, then the edge keeps the copy.
  3. max-age sets how long a copy counts as fresh.
  4. After that, a 304 revalidation sends headers, not the file.
  5. Static files: long max-age plus versioned names like app.3f9c.js.
