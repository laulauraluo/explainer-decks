Explainer · message queues

How a message queue decouples services

Producers and consumers never call each other. Both only talk to the queue.

1 · Producers

Producers push messages and move on

Each service appends a message to the tail of the queue and returns at once. It does not wait for anyone to process it.

2 · Consumers

Consumers pull at their own pace

A worker asks for the next message only when it is free. Each message goes to one worker, taken from the head of the queue.

3 · Backlog

A slow consumer does not block producers

The producer keeps sending 2 messages a second; the worker takes 1 every 2 seconds. The backlog waits in the queue, so watch queue depth.

4 · Acknowledgement

No ack, no delete: the message comes back

A delivered message is hidden, not deleted, until the worker acks it. If the worker dies and the visibility timeout runs out, the queue delivers it again.

Takeaway

Put a queue between services that should not wait on each other

  • Producers stay fast: they only append.
  • Consumers scale alone: add workers to drain a backlog.
  • Failures retry: unacked messages come back.
  • At-least-once: a message can arrive twice, so make handlers idempotent.
